Timeline of bypass:
  20:24:49  — System boot (Recovery Mode reboot cleared OCSP cache)
  20:25:03  — trustd attempts OCSP → times out (pf rules block Apple subnets)

The revoked-certificate app (ChatGPT v1.2026.041, cert revoked May 8, 2026)
launched with full Gatekeeper approval. No "Malware Blocked" dialog appeared.
spctl returned "accepted, source=Notarized Developer ID" — Gatekeeper fully
accepted the revoked-certificate app as if it were legitimate. The user saw
only a standard "downloaded from the Internet" prompt with an Open button,
the same dialog shown for any notarized app. No right-click bypass was needed.

The OCSP cache (repopulated July 22 when DNS poisoning was not active) was defeated by:
  1. Clearing the in-memory OCSP cache via Recovery Mode reboot
  2. Blocking Apple OCSP/CDN subnets via pf firewall rules

This demonstrates that the cache-based defense only protects scenarios
where the victim has PREVIOUSLY and SUCCESSFULLY queried OCSP for that
specific certificate. Fresh Macs, newly revoked certificates, and persistent
attacker networks have ZERO protection.

NOTE (Aug 5, 2026): Previous versions of this document referred to an
"Apple OCSP responder fix deployed July 22." This was incorrect. The
OCSP responder was already serving revocation for this cert (proven by
the July 9 positive control). The cached response appeared on July 22
simply because DNS poisoning was not active at that time.
